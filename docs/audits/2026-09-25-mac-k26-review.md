# mac-papa audit recovery and remediation

Original report: `2026-09-25-mac-k26-original.md`, preserved unchanged.
Requested model: kimi-k2.6 through ir --plain. Served-model attribution was not recorded on the Mac;
the report header does not prove which backend wrote it. The run completed with a report and exit 0;
only the monitoring command timed out. Pack audited: audit-pack-20260925T180658Z, client 0.9.53.

## Findings checked against artifacts

* Confirmed: the 0.9.53 wheel and checksum had never been copied to the site. The live wheel URL
  returned HTTP 404, 21657 bytes of HTML. The prior session's claim that it was shipped was wrong.
* Additional defect: the wheel omitted both Sigstore assets. Export read docs/trust relative to the
  source checkout, and the previous installed-wheel test imported the checkout. 0.9.54 force-includes
  the signed originals as package data. scripts/check_probant_wheel.py executes the exporter from
  only the extracted wheel in an isolated interpreter and fresh working directory. It fails on
  0.9.53 and passes on 0.9.54, checking actual exported bytes and manifest hashes.
* Confirmed: the confidentiality block treated unsigned references as authenticated. 0.9.54 requires
  a signature and supplied key, in addition to the existing all-checks-pass gate. Manually supplied
  unsigned measurements remain usable, but do not earn the authentication claim.
* The OTS failure is a tooling mistake, not a bad proof. The report installed opentimestamps instead
  of opentimestamps-client (already named in VERIFY.md). The updated instructions distinguish them.
  Local ots --no-bitcoin verify derives block 968451 and merkle root
  d1dc4c175ea2518a534d67d2855dfe5c68e03debd0a3f1c9672da788c0edebb3.
  This no-node command does not itself verify a Bitcoin block and returns nonzero here; the
  derived commitment must still be compared with the block. Do not call this a full verification.
* The Sigstore signature verifies over original JSON bytes, or over the digest with Prehashed(SHA256).
  Full cosign verification of the bundle also returns Verified OK with the expected identity
  henry@inferroute.ai and issuer https://accounts.google.com. A raw signature check alone is insufficient.
  The new instructions supply the complete command, tool source, and the prehash distinction.
* An audit on another machine does not make the producer's reference independent of its producer.
  Identity binding, time anchoring, matching measurements, and runtime behavior are distinct claims.
  The previous forecast that moving to the Mac automatically improved claim 3 was too strong.
* No evidence supports the report's sentence that plaintext left the client despite degradation.
  plaintext_bytes_sealed_here is cumulative input to encryption, not transmitted plaintext; the
  refusal event and totals do not give per-request timing. The current request path refuses before
  sending if no verified instance exists. Neither observation proves a historical execution trace.
* Census: 11 receipts, 7 with attestation, so FOUR lack attestation (the report says three).
  All 70 searches report cutoff 20260814, 16000 candidates and zero removals. No document reads.
  The attestation log time 18:00:49Z to pack creation 18:06:58Z is 6m09s, not about 16 minutes.

## Scope of remediation

0.9.54 exports current VERIFY.md alongside its current verifier, instead of preserving stale
instructions from an older record. Existing evidence packs are not edited. The old 0.9.53 wheel
is preserved byte-for-byte for reproducible comparisons; 0.9.54 is the corrected distribution.
No enclave policy, firmware floor, runtime evidence, or historical receipts are changed.
The next audit must form its own verdict; these corrections are not a requested verdict upgrade.
